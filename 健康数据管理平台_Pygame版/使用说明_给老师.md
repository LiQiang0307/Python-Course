# 第九课组框架教学包 · 使用说明

## 一、先回答你的两个问题

**Q1：gui.py 是否不用改前8课组代码、直接调用已有实现？**
基本成立，但不完全。已核实的真实情况：

| gui.py 位置 | 做了什么 | 判定 |
|---|---|---|
| submit() 194/199 | auth.login / auth.register | 直接调用，零改动 |
| save_record 242 / export 251 / report 265 / stats 476 | data.add_record / export_to_csv / generate_report / get_statistics | 直接调用，零改动 |
| handle / change / draw / present | 纯事件与绘制 | 框架本体，与业务无关 |
| **save_record 207–241** | 30行校验＋字段组装（血压拆分、数字转换、value拼串） | **业务逻辑上移到了界面层** |
| **update 292–301** | BMI 现算与结果汇总 | **业务逻辑上移到了界面层** |

结论：数据层（认证/存取/导出/报告）确实零改动复用；但校验组装和评测计算写进了界面。
这不是错误，但恰好是讲"解耦"最好的反面教材——界面干了业务的活。

**Q2：怎么只讲一个框架、让学生填自己的项目？**
看 gui_framework.py：所有业务调用已收敛到 `self.b`（backend 接口），机制部分一行不改。
学生写自己的 `my_backend.py`（照 student_backend_template.py 填空），框架不用动。

## 二、三个文件的关系

```
backend_contract.py      接口契约（8个插槽的签名约定）
        ↑ 继承
student_backend_template.py   学生填空模板 → 学生改造成 my_backend.py
        ↓ 传入
gui_framework.py         通用框架（机制，学生不改），main() 里换 backend 即可
```

## 三、课堂怎么讲（对接二阶引导建构）

- **"查"环节（允许AI）**：让学生对照 gui_framework.py 找出 `self.b.` 的所有调用点，
  归纳出"一个交互程序到底需要业务层提供哪些能力"——这就是插槽清单。
  追问：这些接口换成网页版还成立吗？（验证接口抽象得好不好）
- **"辩"环节（禁用AI）**：抛真问题——"血压格式校验（原207-241行）该写在界面还是业务？"
  先立规则（换界面还要不要这段），再让小组亮观点。这正是文件里"边界辨析"型问题的范本。
- **"验"环节（AI可整理、禁归因）**：让学生把自己命令行项目的函数填进 my_backend.py，
  跑框架、记录哪些插槽一次就通、哪些报错，归因"我的原代码哪里不满足接口约定"。
- **"省"环节（禁生成式）**：课末200字反思——"我原以为写完业务就行，今天发现界面和业务的边界在哪"。

## 四、三道护栏（写进任务卡）

1. **问题清单**：8个插槽分别由你哪一段原代码实现？接口对不上时怎么改？
2. **时间规划**：查15′＋辩15′＋验35′＋归纳10′＋省10′（90分钟2课时）。
3. **产出与AI规则**：当堂交 my_backend.py＋一张"插槽-原代码"对照表；
   查/验可用AI辅助检索与整理，辩/省禁用。

## 五、运行验证

```bash
cd 第9课组_框架教学包
python gui_framework.py        # 用 DemoBackend，先看到框架跑起来的样子
# 学生：把 main() 换成自己的 MyBackend()
```

## 六、一个老实提醒

框架里字体用了 pygame 默认字体（不支持中文显示中文会变方块）。
实际发给学生时，把 gui_framework.py 的 `find_font()` / `font()` 换成原项目的
assets/font.otf（Noto Sans CJK SC），并把 Font(None, size) 改为 Font(字体路径, size)。
本教学包聚焦"框架结构"，中文渲染细节沿用你原项目即可。
